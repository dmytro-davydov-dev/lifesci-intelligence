# Evaluations

The golden dataset lives in `lifesci-test-data/evals/golden-dataset.json`. It has 16 user-supplied synthetic cases, and their labels are checked against the fixture text by `backend/tests/unit/test_golden_dataset.py`. Reports in `reports/` are generated by the runner and committed as produced. Do not edit them by hand.

## Run

```bash
cd backend
# Offline (default): deterministic fake providers, no key, no network
EVAL_DATABASE_URL=postgresql+psycopg://lifesci:lifesci@127.0.0.1:5432/lifesci_eval \
  uv run python -m app.evaluation.run
# Live (opt-in): MODEL_PROVIDER=openai OPENAI_API_KEY=... OPENAI_CHAT_MODEL=... plus the same command
```

The runner resets the evaluation database (its name must end in `_eval` or `_test`). It ingests the sample documents and the INJECTION-001 fixture, then runs every case in `vector` and `hybrid` mode with identical providers and settings. Unscoped cases are restricted to the sample documents, so the injection fixture affects only E15. It writes `reports/<date>-<provider>.{json,md}`.

## Metrics
- **Retrieval:** Recall@1/3/8 and MRR against gold page/section labels. Sections are matched by heading text inside the retrieved chunk.
- **Answers:**
  - Status accuracy.
  - False-abstention rate on answerable cases.
  - Correct non-answer rate (abstention, scope and clarification cases).
  - Literal fact recall: a verbatim, case-insensitive match. It is a lower bound, because paraphrased correct answers score lower.
  - Citation gold precision: whether cited chunks are gold locations. This checks citations point to the right place, not that they support the claim semantically.
  - Injection leaks (forbidden phrases in the answer).
  - Latency p50/p95.
- **Unavailable:** token counts and cost (adapters do not record usage yet), and semantic support (no judge model).

## Current results

`reports/2026-11-24-fake.md` is an **offline run only**. The fake embedder is a hashed bag of words and the fake chat model quotes one sentence. So the answer metrics reflect the stand-in, not model quality, and only the retrieval comparison is meaningful. No live-model run has been executed: there is no API key in this environment.

Observations from that run, on a corpus of 16 cases and 11 chunks:
- Hybrid improved on vector for Recall@1 (0.615 vs 0.500), Recall@3 (0.846 vs 0.769), Recall@8 (1.000 vs 0.923) and MRR (0.838 vs 0.750). Answer metrics were identical in both modes. Hybrid latency p50 was 10.2 ms vs 7.8 ms, for two queries instead of one.
- Metrics are reproducible across fresh ingestions. Tied rankings now break by document name and chunk ordinal; an earlier run that broke ties by random chunk UUIDs produced varying hybrid numbers.
- With top-8 over about 10 sample chunks, Recall@8 is close to saturated. Recall@1, Recall@3 and MRR are the discriminating metrics.
- Failures with the fake model:
  - E13: the scoped question has no supporting evidence in SOP-003, but the fake model answers from term overlap anyway.
  - E16: the fake model never asks for clarification.
  - Comparison cases: the fake model quotes one source only.
  These are limits of the stand-in. A live run is needed to judge them.
- Decision: keep `RETRIEVAL_MODE=hybrid` as the default. Revisit after a live run with real embeddings.
